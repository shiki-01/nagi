## 3. 実装済み・未確認（ビルドを入れたら確認する）

（実装ごとに追記する）

- 診断ログ D-1: 入力テストタブで表示・コピー・消去・記録の ON/OFF（既定 ON）。U-1 の再現ログを取る
- ⌫の長押し連打（加速、離すと停止、入力中はコアの backspace）
- 英字シフト: 1 回で次の 1 文字のみ大文字、0.5 秒以内の 2 回連続で Caps Lock（アイコンと色で区別）
- フリックキー押下時の 4 方向ポップアップ（かな・英字 12 キー）
- JSON レイアウト描画（flick-kana / qwerty-kana / qwerty-alpha / flick-alpha / numbers / symbols / emoji）とモード切替（A/あ、☆123、ABC、😀）。同梱 JSON が読めなければ組み込みにフォールバック
- set_context: 入力開始・確定後・カーソル移動で直前 20 文字をコアへ（パスワード欄では送らない）。診断ログの `set_context` 行で確認
- 設定タブ（`docs/ios-settings.md`）:
  - 上部の「シンプル / 詳細」で項目が増減する。再起動後も選択が残る。切り替えても値は変わらない
  - コアの項目（ライブ変換・LLM・プロファイル・学習・予測など）を変更 → キーボードを開き直さずに（次の focusIn で）反映される。診断ログに `reload_config ok=true` が出る。範囲外の値は項目の下にエラーが出て元に戻る。「キーボードを開き直すと反映」と出る項目（`update.auto_check` など）は開き直しで反映される
  - 設定を 1 つでも変えたあと、キーボードを起動し直しても値が消えない（自動生成の `config.toml` を上書きしない。`conversion.sync_budget_ms` が 30 のままか、変更した値が残るか）
  - 「学習データをすべて削除」→ 確認ダイアログ → 削除。そのあとキーボードで以前の変換候補（学習の順位）が戻らない（診断ログに `clear_learning (signal from host app)`）
  - iOS 固有: トグル入力（オン→同じキー連続タップで あ→い、オフ→タップは「あ」のみ）、フリック感度・判定距離（小さくすると短い移動でフリック）、フリックの案内表示オフ、⌫の連打（開始までの時間・間隔）、キーボードの高さ（低め/標準/高め・倍率）、キーの間隔・角丸、片手モード（左/右に寄る。候補バーは全幅のまま）
  - かな/英字のレイアウト割り当て（`qwerty-kana` を選ぶとローマ字入力になる）が、キーボードを開き直すと反映される
  - 触覚（弱/中/強）: **フルアクセスなし（現状 `RequestsOpenAccess: false`）で振動するか**。しない場合は、触覚にはフルアクセスが要ると判断して案内を出す
  - キー入力の音: 端末の「キーボードのクリック」をオンにして、設定で「システムのクリック音」を選ぶと鳴るか（既定はオフ）
  - 診断ログのオン/オフが、入力テストタブのスイッチと連動する
  - 長押しの判定時間（`flick.long_press_ms`）は保存のみ（長押しの動作が未実装のため効果なし）

## 4. 診断ログ（D-1）

キーボード拡張が、コアとのやり取りとホストへの操作（commit / preedit / marked の内容と長さ）を App Group の
`diag/keyboard.log` に直近 200 行だけ残す。ホストアプリの「入力テスト」タブで表示・消去できる。入力内容を含むため、
デバッグ用であり、リリースビルドでは無効にする（配布前チェック項目）。
