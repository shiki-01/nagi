# iOS 実機テスト手順（キーボードアプリ `frontend-ios`）

- 版: 2026-10-04
- 対象: `frontend-ios/`（本体アプリ `Nagi` + キーボード拡張 `NagiKeyboard`）。辞書のみ（`minimal`）、LLM なし、曖昧入力（`[fuzzy] enabled = true`）有効
- 位置付け: M0 の実測（`frontend-ios-spike/`）とは別。ここは「キーボードとして実際に使えるか」の確認と、不具合・較正データの回収が目的
- 関連: `frontend-ios/README.md`（ビルド・レイアウト JSON）、`docs/fuzzy-input-design.md`（曖昧入力）、`docs/mobile-roadmap.md`

## 1. ユーザー側で必要なもの

| 項目 | 内容 |
| --- | --- |
| 端末 | iPhone 実機（シミュレータはメモリ上限・キーボード拡張の挙動が異なるため不可）。iOS のバージョンを控える |
| 導入ツール | SideStore（スパイクと同じ。無料 Apple ID）。スパイク（`NagiSpike`）が入っていても Bundle ID が別なので共存できるが、**無料 Apple ID の制限（有効アプリ 3 個、App ID は週 10 個）**に注意。スパイクを消す場合は先に結果の回収を済ませる |
| IPA の入手 | GitHub Actions の **ios-app** ワークフロー（作業ブランチ `claude/amazing-mccarthy-3bg0ge` の push で自動実行。main に取り込めば手動実行も可）の artifact **`Nagi-unsigned.ipa`**。実行結果は Actions タブで確認 |
| 回収用の連絡手段 | 診断テキストを貼るためのチャット（診断は入力欄に挿入するか、クリップボードへコピーされる） |

こちら（AI 側）で完了していること: Rust コア・FFI・Swift の実装、CI でのビルド成功（未署名 IPA の生成、ldid による App Group entitlement の埋め込み、シミュレータの単体テスト）。**実機での動作は未確認**。

## 2. 導入手順

1. Actions の最新の ios-app の run を開き、`Nagi-unsigned.ipa` をダウンロードして端末へ送る（AirDrop・ファイル App 等）
2. SideStore の「+」から IPA を選んでインストール（スパイクと同じ手順）
3. 設定 > 一般 > キーボード > キーボード > 新しいキーボードを追加 > **Nagi**
4. 追加した Nagi をタップ。**「フルアクセスを許可」はオフのまま**（不要。ネットワークは使わない）
5. 本体アプリ `Nagi` を開き、「状態」を確認する（下記 §3-1）
6. 本体アプリの「テスト入力」欄、または任意のアプリの入力欄で 🌐 を長押しして Nagi を選ぶ

## 3. テスト項目（優先順）

### 3-1. 起動・メモリ（最優先。ここが通らないと以降が意味を持たない）

**最大のリスクは拡張のメモリ上限**。辞書（約 56MB のファイル）は現在ヒープに全量読み込む（mmap 化 = D-1 は未実施）。拡張が起動直後や変換時に OS に強制終了される場合は、D-1（辞書の mmap 化）が必要になる。

- 本体アプリ「状態」: エンジンのバージョン、辞書の有無と出所（App Group / バンドル）、App Group の可否、`config.toml` の状態
- 「自己テストを実行」: `nihongo` が Space 変換されるか、レイテンシ、`phys_footprint`（メモリ）。**数値を控える**
- キーボードを開いて入力欄に切り替えた直後に落ちないか（落ちる場合: 切り替え直後に標準キーボードへ戻る、または表示が崩れる）。キーボード上部の **ⓘ** をタップすると診断が入力欄に挿入される（メモリ・p50/p95・ログ）
- 何度か（10 回程度）🌐 で切り替えを繰り返し、メモリが増え続けないか（ⓘ の診断で確認）
- 回収: 上記の数値と、落ちた場合はその状況（どの操作の直後か）

### 3-2. QWERTY ローマ字

- `nihongo` → Space → 「日本語」が先頭に出る → 候補タップ or ⏎ で確定
- 文節をまたぐ文（`kyouhaiitenkidesu`）を Space 変換し、候補バーの ◀ ▶（注目文節）、縮/伸（区切り）が効くか
- Backspace（1 回で 1 文字消える、長押しで連打）、Space（未変換時は半角スペースか）、⏎（未確定なら確定、無ければ改行）
- 大文字・数字・記号の混入（`Tokyo2026` 等）、英数面（direct）への切替
- 入力中に別の欄をタップ、アプリを切り替える → 未確定文字列が失われない・確定される
- 回収: おかしな挙動の再現手順

### 3-3. フリック 12 キー

- 各行のフリック 5 方向（タップ・左・上・右・下）が意図どおりのかなになるか
- 「小゛゜」で濁点・半濁点・小書きの切り替え（`か`→`が`→`か`、`つ`→`っ` 等）
- 変換（Space）・候補選択・確定、Backspace
- **フリックの方向判定が敏感すぎる・鈍いと感じるか**（`FlickGeometry.spreadRatio` と判定しきい値の較正に使う）。感じた方向・キーを記録

### 3-4. 曖昧入力（今回の主目的の一つ）

補正は「Space を押したときの候補リストの 4 番目付近（先頭 3 件の後ろ）」に出る（打った文字は書き換わらない）。候補に補正（出所「補正」）が付くか確認する。

- タイポ: `nihn`（にほん）、`kanizi`、`konnitiha` など。Space → 候補末尾に補正が出るか
- タッチずれ: 隣のキーに掛かるように、わざとキーの端を押して打つ。**意図した語が候補に出るか**
- フリックずれ: 方向の境目をわざと狙って出す
- **誤補正（劣化）**: 正しく打った入力で、補正が候補を邪魔しないか（先頭候補が変わっていないか）。補正が出て邪魔に感じたケースを記録
- **Space 変換が遅くならないか**（補正が走る入力で、候補が出るまでの体感。ⓘ の診断の p95 を控える）。目標: 150ms 以内

**既知の状態（2026-10-04）**: 合成ノイズの評価（開発機・release・実辞書）では、ノイズ無し入力の劣化は 0/1000、補正あり Space 変換の p95 は約 12ms（補正なし 0.5ms）。30 打鍵クラスの長い入力では補正の計算だけで約 32ms かかる。端末ではこれより遅くなるため、実機の p95 を §4 で回収する。補正候補は注目文節の候補リストの 4 番目付近に挿入される（先頭 3 件の後ろ）。

### 3-5. 学習・設定

- 同じ語を何度か確定して、次回の候補順位が上がるか（学習はアプリの `user_dir` に保存される）
- 本体アプリで設定の変更・学習データの削除ができるか（実装範囲は README を参照）

### 3-6. 常用テスト（1〜2 日）

- メッセージ・メモ・ブラウザの検索欄など普段使うアプリで実際に使う。**困った場面**（変換が遅い、候補が出ない、落ちる、改行できない、アプリごとの不具合）を日時・アプリ名付きで記録
- パスワード欄（iOS が標準キーボードに切り替える）、URL 欄・メール欄・数字欄（自動で英数/数字面になる）

## 4. 回収してほしい情報

1. 端末機種・iOS バージョン
2. §3-1 の自己テスト結果（メモリ・レイテンシ）と、ⓘ の診断テキスト（入力欄に挿入されたものをそのまま）
3. SideStore で App Group が使えたか（本体アプリ「状態」の App Group）
4. 不具合の再現手順（アプリ名・入力列・期待と実際）
5. 曖昧入力: 補正が出た/出なかった例、邪魔だった例（入力列と候補）。タッチずれの傾向（親指で届きにくい位置、左右どちらにずれやすいか）
6. 操作感: フリックの方向判定、キーの大きさ・高さ、候補バーの見やすさ

ログ・診断には入力内容を含めない設計だが、不具合の再現手順として入力列を書く場合は、個人情報を含まない例にすること。

## 5. 想定される問題と切り分け

| 症状 | 想定原因 | 切り分け・対応 |
| --- | --- | --- |
| キーボードに切り替えると落ちる／すぐ標準に戻る | メモリ上限（辞書のヒープ全量読み込み）、辞書が見つからない | 本体アプリの「状態」で辞書の出所、自己テストのメモリ値。落ちるなら D-1（mmap 化）を実施 |
| 辞書が見つからない | ビルドで辞書が拡張のバンドルに入っていない | 「状態」の辞書出所。CI の「辞書を拡張のリソースへ配置」ステップのログ |
| App Group が使えない | 無料 Apple ID で SideStore が付与できない | 想定内。拡張専用の領域で動く（本体アプリとは設定・学習が共有されない。カスタムレイアウトの取り込みも拡張から読めない） |
| 未確定文字列の下線が出ない・位置がおかしい | `setMarkedText` がホストアプリと合わない | ⓘ を長押しして「バー上部のみ表示」に切り替える |
| 変換が遅い | 補正の仮説生成（長い入力で約 30ms 級。端末では増える）、端末性能 | `[fuzzy] enabled = false`（`config.toml`。本体アプリの設定）で比較。診断の p95 |
| 入力がたまに消える | エンジンの再初期化（パニック捕捉）→ `restore_session` | ⓘ の診断ログの再初期化回数 |
| 7 日後にキーボードが使えなくなる | SideStore の再署名の失効 | SideStore の更新。OS 標準キーボードに戻るだけで入力は失われない |
