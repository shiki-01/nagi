# 公開前の整理メモ

作成: 2026-09-30。公開時に見せたくない内容の扱いを検討した記録です。方針は未決定です（下記「選択肢」参照）。

## 他製品への言及
- 参考実装として Mozc・azooKey・karukan・Mozkey などの名前を挙げること自体は、OSS では一般的で問題になりにくい。
- 要確認: 他製品のコードや辞書データを取り込んでいる箇所がないか。挙動や数値の参照（例: Mozkey の実測既定値、Mozc 原本との照合）であれば問題は小さい。取り込みがあれば、ライセンス表記が別途必要。
- 特定製品への批判的な評価や個人の使用感を含む記述は、公開向けに書き直す。

## 見せたくないもの
- `CLAUDE.md`（サブエージェント委任方針を含む開発者用の内部設定）: `.gitignore` に入れるか、公開用は要約のみにする。
- `docs/decisions.md`・`docs/progress.md`: 試行錯誤や「要レビューの暫定判断」が中心。設計書 `docs/ime-design-doc.md` と分けて扱う。
- コミット履歴: `Co-Authored-By`・セッション URL・docs の過去版が残る。ファイルを後から消しても履歴から読める。

## 選択肢
1. 公開用リポジトリを新規に作る（推奨）。整理した状態で履歴を新しくし、内部用 docs は非公開リポジトリか別ブランチで管理する。
2. 現リポジトリの履歴を書き換えてから公開する（`git filter-repo` 等）。全コミットのハッシュが変わり、force push が必要。
3. 公開しない部分だけを外して現履歴のまま公開する。履歴から読めるため、目的には不十分。

## 公開前の確認事項
- 履歴に秘匿情報（トークン・パス等）が混じっていないかの検査
- `LICENSE-MIT` / `LICENSE-APACHE` の存在
- 辞書・モデルがリポジトリに混入していないこと
- docs と履歴を走査し、他製品の言及箇所と公開に不向きな記述を一覧化する（未実施）
