# 計画: カタカナ語の翻訳候補（外来語 → 原語）

状態: **計画**（2026-10-23、ユーザー依頼）。実装は未着手。決定ログは `docs/decisions.md` H-47。

## 目的

変換候補に、カタカナ語の原語（英語など）を出す。

- 例: `こんぴゅーたー` → `コンピューター` の候補に加えて `computer`
- 例: `あるばいと` → `アルバイト` に加えて、原語の `Arbeit`（ドイツ語）
- 単語ごとに判定する。読みの判定は多少ゆるくして、ある程度のカタカナ語は自動で候補に出る

## 結論

- **データ（JMdict）に、外来語の原語の言語が単語ごとに入っている**ので、原語がどの言語でも（英語・ドイツ語・フランス語など）、その綴りをそのまま候補に出せる。言語の選択は設けない
- 「任意の言語への翻訳」は、このデータだけではできないうえに、不要とのことなので範囲外
- 規模は中。データの取り込みが小〜中、コアへの組み込みが小、設定が小

## データ

- 第一候補は **JMdict**（EDRDG。日本語-多言語の辞書）。外来語の項目に、原語の言語（`lsource` の `xml:lang`。`eng`・`ger`・`fre`・`por`・`dut` など）と原語の綴りが付いている。和製英語（`ls_wasei`）の印もある。**この構造は記憶に基づくので、実装の最初にデータの実物で確認する**
- ライセンスは EDRDG のもの（CC BY-SA 4.0 とされる。**要確認**）。Nagi は MIT OR Apache-2.0 なので、**同梱せず、Mozc 辞書と同様に取得して利用者の Mac で索引を組み立てる**（`docs/ime-design-doc.md` §2.3、`nagi-datafetch`）。出典の表示（`NOTICE`）は必要
- 索引: カタカナの表記（正規化したもの）→ 原語の言語・綴り・和製英語かどうか。数万件ではなく、外来語に絞れば約 1 万件規模。メモリ・サイズの負担は小さい

## 方式

1. **候補にする対象**: 変換結果（または辞書候補）にカタカナのみの語があるとき。文節ではなく、カタカナの連続（語）ごとに判定する
2. **照合（読みのゆるさ）**: カタカナ表記を正規化して引く。ゆるくする内容:
   - 長音の違い（`コンピュータ` と `コンピューター`、`ー` と母音（`う`・`お`）の揺れ）
   - 小書き・表記の揺れ（`ヴ` と `ブ`、`ティ` と `チ`、`ウィ` と `ウイ`、`ファ` と `ハ` など）
   - 中黒（`・`）の有無、促音・撥音の揺れ
   - さらに、正規化した骨格（長音と母音の細かい違いを落としたもの）の編集距離が 1 以下のものは、順位を下げて候補にする
3. **複合語**: 索引に無いカタカナの連続は、既知の語の最長一致で分割して、各語の原語を空白区切りで並べるか、候補にしない（初期は候補にしない。誤訳を避ける）
4. **和製英語**: `ls_wasei` の語（例: サラリーマン、マンション）は、原語として正しくない綴りになりうるので出さない

## 見せ方・並び

- 出所の注記は「翻訳」（`CandidateSource` に値を足すと、プロトコルの型（Swift/Rust）に触れるので、初期は既存の `Rewriter` を使う。必要なら加算的に追加する）
- 並び: 通常の変換候補（辞書・LLM）のあと、記号などの Rewriter の候補と同じ位置。「形式の変換」（ひらがな・カタカナ・全角・半角）より前

## 設定

- `[convert.loanword] enabled`: カタカナ語の原語を候補に出すか（既定: 出す）
- 出す言語の選択（英語のみ・原語のまま、など）と、任意の言語への翻訳は**作らない**（ユーザー決定、2026-10-23）。出すのは、データにある原語の綴りそのまま（英語の語は英語、ドイツ語の語はドイツ語）
- 和製英語の扱いと、読みのゆるさは、設定にせず固定にする（和製英語は出さない。読みのゆるさは「標準」）

## 難所

- **誤訳**: ゆるい照合は、別の語を原語として出してしまう。→ ゆるい一致は順位を下げる（編集距離 1 以下に限る）
- **多義**: 1 つのカタカナに複数の原語がある（例: `ガード`: guard / girder）。→ 頻度・優先度の付いた順で複数出す（最大 3 件程度）
- **原語の綴りの大文字・小文字**: 辞書の綴りに従う（固有名詞は大文字）

## 実装の順序（案）

1. JMdict の実物で、`lsource` の構造・言語の種類・和製英語の印を確認する。取得と索引の組み立てを `nagi-datafetch` に足す
2. カタカナの正規化と照合。評価用の語（外来語 200 語程度。正解の原語つき）で、取りこぼし率と誤訳率を測る
3. エンジンの候補生成に組み込む（Rewriter の 1 つとして）。オン・オフの設定項目を足す
4. 設定 GUI（コアの記述子 `get_settings` に項目を足すだけで、フロントのコードは不要）
